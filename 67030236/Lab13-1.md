### กิจกรรมที่ 13-1.3: การสั่งรันและทดสอบด้วยเครื่องมือ CLI

#### 1. สั่งรัน Kestrel Edge Gateway
```powershell
dotnet run
```
*สังเกตข้อความบนคอนโซลว่าเซิร์ฟเวอร์กำลังฟังที่พอร์ต 5000 (HTTP) และ 1883 (MQTT)*

#### 2. เปิดหน้าต่าง PowerShell ที่สอง: ทดสอบ Subscribe หัวข้อ
ใช้คำสั่ง `mosquitto_sub` เพื่อดักฟังข้อความจาก Embedded Broker ของเรา (ระบุพารามิเตอร์ `-i` เพื่อกำหนด Client ID):
```powershell
mosquitto_sub -h 127.0.0.1 -p 1883 -t "test/edge/topic" -i "sub_client" -v
```
> **ข้อสังเกต:** มาตรฐาน MQTT กำหนดให้ Client ต้องมี Client ID เสมอ สำหรับเครื่องมือ `mosquitto_sub` บน Windows หากไม่ระบุออปชัน `-i` มันจะส่ง Client ID ว่างเปล่ามา ซึ่งในโค้ดฝั่ง Broker เราได้ตั้งค่า `ValidatingConnectionAsync` ให้สุ่ม Client ID ให้โดยอัตโนมัติแล้ว

*สังเกตหน้าต่างคอนโซลของ Kestrel จะขึ้นข้อความสีเขียวว่ามี Client เชื่อมต่อเข้ามา!*

#### 3. เปิดหน้าต่าง PowerShell ที่สาม: ทดสอบ Publish ข้อความ
ส่งข้อความผ่าน `mosquitto_pub`:
```powershell
mosquitto_pub -h 127.0.0.1 -p 1883 -t "test/edge/topic" -m "Hello from CLI via Kestrel Embedded MQTT!" -i "pub_client"
```

#### 4. สังเกตผลลัพธ์

* หน้าต่าง `mosquitto_sub` จะได้รับข้อความที่ถูกส่งต่อผ่าน Broker สำเร็จทันที

## 4. คำถามท้ายการทดลอง (Review Questions)
1. การรัน Embedded MQTT Broker ภายใน Kestrel มีข้อได้เปรียบกว่าการติดตั้งซอฟต์แวร์ Mosquitto แยกต่างหากอย่างไรในแง่ของการกระจายงาน (Deployment) และการประมวลผลข้อมูลในหน่วยความจำ?
```
1. ด้านการกระจายงาน (Deployment)Single Binary / Single Container: รวมแอปพลิเคชันหลัก (Web API/Background Service) และ MQTT Broker ไว้ในโปรเซสหรือ Container เดียวกัน ลดภาระการคอนฟิก/ดูแลระบบ (ไม่ต้องจัดการ systemd, Docker compose หรือเครือข่ายระหว่าง Container เพิ่มเติม)การจัดการ Lifecycle และ Config ร่วมกัน: ควบคุมการ Start, Stop, Health Check และโหลดการตั้งค่า (เช่น AppSettings, Environment Variables, TLS Certificates) ผ่านโค้ดและ CI/CD pipeline เดียวกันทั้งหมดAuthentication/Authorization แบบ Native: ตรวจสอบสิทธิ์ผู้ใช้หรืออุปกรณ์ได้โดยตรงผ่านระบบ Authentication และ Dependency Injection (DI) เดิมของ .NET (เช่น Database, JWT, OAuth) โดยไม่ต้องทำ Mosquitto Auth Plugin หรือเชื่อมระบบยืนยันตัวตนภายนอก

2. ด้านการประมวลผลข้อมูลในหน่วยความจำ (In-Memory Processing)   Direct In-Memory Hook (Zero Network Hop): เมื่อมีข้อความ MQTT เข้ามา โค้ดของแอปพลิเคชันสามารถดักจับ (Intercept) ผ่าน Event/Interceptor ภายใน RAM ได้ทันที ไม่ต้องมี Client ตัวอื่นมา Subscribe ผ่าน loopback network (TCP/Sockets)ลด Overload และ Latency: ตัด Overhead ของ IPC (Inter-Process Communication), TCP stack และการ Serialize/Deserialize ซ้ำซ้อนZero-copy / Memory Sharing: ใช้ประโยชน์จาก Span<T>, Memory<T> หรือ System.IO.Pipelines ของ Kestrel เพื่อส่งต่อ payload ไปประมวลผลต่อ (เช่น ส่งเข้า Channel, SignalR หรือบันทึกลง Database) ได้ทันทีด้วย memory overhead ที่ต่ำมาก
```
