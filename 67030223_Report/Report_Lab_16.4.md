**สรุปผลการทดลอง:**    
สามารถบูรณาการระบบนิเวศ IoT ครบวงจร (End-to-End Multi-Protocol IoT Ecosystem) ได้สำเร็จ โดยใช้ Kestrel Edge Gateway (.NET 8) เป็นศูนย์กลางเชื่อมโยงข้อมูลข้ามทุกเลเยอร์: ฮาร์ดแวร์ ESP32 (Serial UART) $\leftrightarrow$ Embedded MQTTnet Broker $\leftrightarrow$ Web Dashboard (SignalR WebSockets) $\leftrightarrow$ Flutter Mobile App $\leftrightarrow$ Third-Party REST API ระบบผ่านการทดสอบ The Grand Verification Matrix ครบทั้ง 4 มิติ ข้อมูลโทรมาตรซิงค์ตรงกันทุกหน้าจอแบบเรียลไทม์ คำสั่งควบคุมหลอดไฟ LED ซิงค์สถานะสองทางได้จากทุกช่องทางอย่างไร้รอยต่อ และผ่านการทดสอบ Local Survivability โดยระบบยังคงทำงานได้สมบูรณ์แม้ตัดการเชื่อมต่ออินเทอร์เน็ตภายนอก


**คำถามท้ายการทดลองที่ 1:**    ตลอดระยะเวลา 13 สัปดาห์ การเดินทางจากระดับบิตและรีจิสเตอร์ของเซนเซอร์ สู่เฟรมเวิร์ก FreeRTOS, ผ่านโปรโตคอลเครือข่ายท้องถิ่น, สู่ระบบคลาวด์ MQTT, หน้าจอมือถือ Flutter, และมาบรรจบที่ Kestrel Edge Gateway... สถาปัตยกรรมชิ้นใดที่ท่านคิดว่ามีความท้าทายเชิงวิศวกรรมมากที่สุด? เพราะเหตุใด?    
**คำตอบ:**    Converged Edge Gateway (.NET 8) มีความท้าทายมากที่สุด เพราะต้องประสานการทำงานแบบ Asynchronous ข้าม 4 โปรโตคอลพร้อมกัน (Serial, MQTT, REST, WebSockets) ภายใต้โปรเซสเดียว ต้องออกแบบ In-Memory State Store ให้รองรับ Concurrency ป้องกัน Race Condition และหลีกเลี่ยง Thread Blocking จาก Serial I/O เพื่อให้ทุกหน้าจอซิงค์สถานะตรงกันแบบ Sub-second Latency

- **คำถามท้ายการทดลองที่ 2:**    หากท่านต้องนำระบบนี้ไปติดตั้งในโรงงานอุตสาหกรรมจริง สิ่งใดคือ 3 ปัจจัยแรกที่ต้องดำเนินการเพิ่มเติมเพื่อความปลอดภัยและความมั่นคงระดับองค์กร?    
**คำตอบ:**    1.การเข้ารหัสและยืนยันตัวตน (TLS/mTLS & Auth): เปิดใช้ HTTPS/WSS (พอร์ต 5001) และ MQTTS (พอร์ต 8883) พร้อมบังคับใช้ API Keys, JWT Token หรือ Client Certificate เพื่อป้องกันการดักฟังและการสั่งการโดยไม่ได้รับอนุญาต

2.ระบบกักเก็บข้อมูลท้องถิ่น (Local Data Buffering / Store-and-Forward): นำฐานข้อมูล Time-Series (เช่น SQLite หรือ InfluxDB) มาบันทึกข้อมูล Telemetry ลงเกตเวย์ยามเครือข่ายขัดข้อง ป้องกันข้อมูลสายการผลิตสูญหาย

3.การแบ่งโซนเครือข่ายและฮาร์ดแวร์ระดับอุตสาหกรรม (Segmentation & Watchdog): แยก VLAN ฝั่งควบคุม (OT) ออกจากฝั่งออฟฟิศ (IT) พร้อมเปิดใช้ Hardware Watchdog และคอนฟิก Serial/RS-485 ให้ทนสัญญาณรบกวนในโรงงาน
